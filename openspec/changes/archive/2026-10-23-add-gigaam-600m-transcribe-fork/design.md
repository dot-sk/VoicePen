## Context

See `proposal.md` for scope. The initial upstream baseline is `handy-computer/transcribe.cpp` v0.4.0, commit `1dc22facfc931e2f8adb43924b0e38b9c46f83c7`. Its converter lists four GigaAM v3 variants. The existing GigaAM encoder has dynamic dimensions and appears to share the 600M checkpoint's Conformer ordering, pre-projection RoPE, and layer normalization. This supports investigating reuse; it does not establish tensor or inference parity. Upstream issue [87](https://github.com/handy-computer/transcribe.cpp/issues/87) tracks the missing multilingual support.

The measured floating artifact is `ai-babai/gigaam-multilingual-mlx`, whose manifest traces it to `ai-sage/GigaAM-Multilingual` revision `3905cd51c3ed4e88c8edf33f3302969ba480a327`. The local F16 weights have SHA-256 `d6d7bcef5e1b77700c84d669635a88021724fd3b1ae0c408890bccdf3c8d2269`. Its profile is `multilingual_large_ctc`, approximately 585M parameters, 24 layers, dimension 1024, 16 attention heads, 64 mel bins, subsampling factor 4, RoPE base 5000, and 71 CTC classes including blank. The manifest records 75 transposed Conv1d tensors. These are conversion inputs to verify, not permanent API constants.

Current upstream v3 inference uses 25-second encoder windows with overlap and stitched CTC decoding. The measured MLX reference processes each corpus recording as one input. Most accepted recordings exceed that window, so unchanged v3 windowing cannot establish parity. Local research under `.local/asr-quality/evaluations/gigaam600m-transcribe-metal-20261019/` supplies the evidence below; it does not complete the maintained fork's release gates.

The concurrent research conversion produced a 1,172,218,464-byte F16 GGUF with 824 tensors and 75 Conv1d layout reversals. A smoke request on the 22.72-second `sample-022` loaded on `MTL0`, returned success, and produced Russian speech text. Its timing included tensor dumps and is not an accepted latency result. The first upstream all-tools configuration with examples disabled failed because `transcribe-bench` could not find `wav.h`; the final research setup built the required CLI, benchmark, and quantizer targets after correcting the build configuration. The initial failure remains in the research logs. Packaging still needs a clean supported build matrix and the full applicable native tests.

The initial `sample-022` comparison produced exactly matching decoded text, mel cosine similarity `0.999999999996`, encoder cosine `0.99986353`, logits cosine `0.99993285`, and frame argmax agreement `99.6479%`. Native activations were F32 while reference MLX activations were F16; logits maximum absolute difference was `2.406` and mean absolute difference `0.0246`. The encoder result would miss the proposed cosine gate if treated as a matched pair. This mixed-dtype probe is not a valid numerical acceptance comparison; do not relax the gate to accommodate it.

A subsequent matched-F32 diagnostic using the same F16-valued weights passed cosine >= `0.99999` and NRMSE <= `0.001` for the sampled mel, subsampling, blocks 0/11/23, final encoder, and logits checkpoints, with exact decoded text. Encoder cosine was `0.999999866` with NRMSE `0.0005174`; logits cosine was `0.999999932` with NRMSE `0.0003677`. Research found that two intermediate attention/convolution dump pointers lacked lifetime marking and could reflect reused scheduler memory. After correcting the instrumentation, all ten sampled checkpoints passed, with maximum NRMSE `0.0005174` and minimum cosine `0.999999866`. This resolves the dtype-confounded probe at those checkpoints, but does not cover every encoder layer. Completed research process exit codes alone do not establish corpus quality acceptance.

The final research `report.md` covers 27 recordings with three calls per recording, four CPU threads, no timestamps/prompt/vocabulary, and load/warmup excluded. The following are measured research results, not accepted package claims:

A complete one-pass MLX run using F32 activations and the same F16-valued weights matched native output on all 27 recordings. This establishes full-corpus decoded fidelity for that documented arithmetic pair, without a matched-F32 latency claim. The default F16-activation baseline remains a separate quality comparator, including its slightly different scores; this reviewed alignment of activation arithmetic does not change gold references or numerical tolerances. The stock-window result is now the selected primary candidate because of its measured quality. Its acceptance needs a matching windowed oracle and boundary tests; whole-input parity remains separate model-computation evidence. Q8 is slower than native F16 in these measurements and has no assumed quantization speed benefit. Complete per-layer, language, interface, upstream regression, clean packaging, and release gates remain outstanding. Read the final research JSON and policy hashes when implementing; these figures must not become fixed product thresholds.

The completed CTC head A/B used one final library/model, separate sessions, per-shape warmup, and three alternating-order pairs per recording. All 81 CPU/GPU pairs had identical text and identical quality under all four scoring policies. CPU/GPU end-to-end medians were `0.217171`/`0.214921` seconds; sums of the 27 recording medians were `6.556376`/`6.528761` seconds, a `0.42%` reduction. The paired median delta was `-2.119` milliseconds, but the bootstrap 95% interval for mean recording delta was `[-2.332, +0.348]` milliseconds and crossed zero. Short logits had cosine `0.9999999984`, maximum absolute difference `0.001395`, and 100% frame argmax agreement. Host decode fell from `1.906` to `0.046` milliseconds and readback from `0.218` to `0.034` milliseconds; earlier larger decode times included dump overhead and are not the baseline. Graph timing includes encoder plus GPU projection, without isolated kernel timing. The GPU candidate also omitted argmax-unnecessary log-softmax, so the experiment compares complete head paths rather than matmul alone.

The measured end-to-end benefit is inconclusive. Keep the simpler host CTC projection as the planned supported baseline. Preserve the GPU research result as an optional optimization candidate, without adding it as a required shipping path. Evidence lives in the ignored research root as `report.md/json`, `head-ab-report.md/json`, `parity-f32-activations.json`, provenance/hash manifests, and `source.patch`; it does not replace tests or package validation in the maintained fork.

### Preserved implementation handoff

The existing prototype is preserved in this change's [research handoff](research/README.md), including the byte-identical converter and benchmark/reference/scoring scripts, their frozen source dependencies, the five-file upstream patch, license notice, and file digests. `research/manifest.json` identifies every preserved source. Detailed benchmark results, full reports, private corpus, model files, libraries, and tensor dumps remain local; `implementation-evidence.md` summarizes the conclusions needed for review.

Apply starts by promoting these assets, not by writing the converter or runtime experiment again. The prototype already accounts for 824 tensors and 75 Conv1d transforms, runs the multilingual GGUF through the parameterized encoder, and provides matched-compute probes and complete corpus outputs. Its whole-input/GPU-head flags and profiling are research paths. The primary candidate reuses the upstream stock window planner and host head. Production work remains in metadata validation, complete language/capability handling, matched-window reference export, boundary/error/cancellation fixtures, native regression coverage, and clean packaging. The converter's current ru/en/kk metadata is incomplete for the full checkpoint language list and must be reviewed during promotion.

## Goals / Non-Goals

Goals are promotion of the preserved prototype into a small maintained fork, the selected F16/stock25 profile, checkpoint-faithful model computations, optional Q8 acceptance, and a tested package that a Swift client can consume. Python conversion, reference inference, and tensor export remain offline tools.

This change does not wire a dependency into VoicePen, add model choices or defaults, alter application recognition controls, implement Meeting integration, change the accepted corpus references, or publish a hosted fork/model/library release. CPU encoder inference may be used as a numerical diagnostic in development. The Metal-required baseline keeps the encoder graph on Metal and the existing frontend and CTC projection/search on the host, as selected from the current inconclusive head-placement experiment. It must not fall back to a CPU encoder or advertise full GPU inference while model computation remains on the host.

## Decisions

### Own a small pinned fork and reuse the existing C interface

Maintain the new profile, converter, regression fixtures, and packaging changes as a reviewable patch series against the upstream commit. Pin upstream, fork commit, ggml revision, compiler/SDK, build flags, converter environment, and checkpoint separately. Keep the existing C ABI where it already represents the contract, including capabilities, status results, abort callbacks, backend requests, and ownership. Any necessary additive extension must preserve existing callers and gain a C and Swift compatibility test.

Use an isolated dynamic macOS arm64 XCFramework, statically containing private ggml, with exports restricted to the public C ABI. Embed the Metal source resources in this framework binary so resource lookup does not consult another bundle or process-global overrides. The embedded build compiles out the upstream Objective-C resource lookup class entirely, avoiding its global registration. Preserve a unique class prefix in non-embedded diagnostic builds. Use a C module map, the required Metal resources, a minimal Swift import client, and a manifest of contents and digests. Use macOS 15.0 as the minimum deployment target, matching the current repository, and verify on that target before acceptance. Keep packaging local until a separately authorized publication decision. Do not change VoicePen's Package.swift or build scripts in this change.

Alternative: ship Python/MLX. It preserves the current research path but adds a second inference environment and does not meet the native runtime goal. Alternative: wait for upstream support. This avoids fork ownership but provides no controlled delivery path. Proposed ADR-0013 records the chosen maintenance cost.

### Convert the floating checkpoint before quantizing

Use the pinned F16 artifact and its manifest as the initial conversion input, retaining original upstream checkpoint provenance. Verify all source tensors, dtypes, shapes, checksums, and config fields. Reverse the recorded MLX Conv1d layout changes explicitly and check every transformed tensor against a round-trip fixture. Preserve vocabulary order and blank index; do not infer them from token text or assume the Russian v3 profile.

Emit a distinct versioned multilingual profile in GGUF. Include one CRC32 for each serialized tensor in catalog order and validate it before exposing a ready model, using the already vendored miniz implementation. This detects payload corruption independently of shape checks. Whole-file SHA-256 in the package/model manifest remains the cryptographic artifact identity; CRC32 is not an authenticity mechanism. Quantized artifacts must regenerate their payload integrity metadata before becoming eligible for loading and acceptance. Reject unknown profiles, unsupported metadata versions, surplus/missing tensors, inconsistent shapes, and vocabulary/class mismatches. Quantize native Q8 from the verified floating conversion using a pinned ggml tool and an explicit per-tensor type map. The measured MLX INT8 group-size-64 artifact is a comparison baseline only. Its format and quantization error are not equivalent to ggml Q8.

### Promote F16 with the measured stock window policy

Keep v3's behavior unchanged and use the measured stock planner for the new primary F16 profile. The existing planner uses encoder windows of at most 625 frames at the profile's 40 ms frame rate, with up to 50 context frames per side. For long input it distributes equal retained spans, encodes each span with context, discards context-only encoder frames, stitches the retained frame sequence, and performs one greedy CTC decode. The 25-second maximum includes context. Short input uses a single pass. Preserve this exact policy with a versioned identity in the package manifest and diagnostics; do not implement overlapping WAV transcription followed by text merging.

The user selected this F16/25-second candidate after reviewing its measured quality. Whole-input remains a diagnostic context for checking conversion and individual model computations; its completed 27/27 matched-compute text check does not certify window stitching. Add an independent MLX F32 window oracle with the same full-recording frontend, retained/context spans, window-local positions, frame selection, stitched sequence, and one CTC collapse. Compare native windowed inference with that oracle and preserve the frozen research `f16-stock25` outputs and all scoring protocols. Add fixtures immediately below/at/above window thresholds, cross-boundary speech, genuine repeated words and blank transitions, short-tail cases, and the longest corpus input. Do not weaken numerical gates or alter gold references when switching the acceptance context.

The supported profile must select its window policy through normal versioned configuration rather than research environment overrides. Reject resource exhaustion explicitly without truncating the recording or silently selecting whole-input/another policy. Retained frame coverage must be exact and cancellation must be observed between windows.

### Establish floating parity before accepting quality results

Freeze a deterministic diagnostic fixture set containing digital silence, an impulse, seeded noise, short Russian and English speech, a supported non-Russian/non-English language sample, and cross-boundary speech. Synthetic fixtures cover math and edge cases; licensed or private speech fixtures carry provenance. The private 27-recording corpus does not establish accuracy for every advertised language. Language metadata remains checkpoint-derived, while at least one sample per advertised language must exercise token decoding without asserting a broad accuracy claim.

Run the floating reference with the pinned F16-valued weights, F32 activations matching native inference, no quantization, greedy CTC, identical samples, and an explicitly matched context. Use whole-input and individual windows for model-computation diagnostics and the matched stock-window oracle for primary-path acceptance. F16 identifies native weight storage, not an F16-activation promise. Save reference frontend tensors, subsampling output, each encoder block, final logits, frame argmax, and collapsed token IDs. Use F32 native diagnostic storage made from the same logical F16 weight values to isolate conversion/graph differences from backend arithmetic. Record storage, activation, accumulation, and projection precision separately wherever known. Keep default MLX F16-activation results as an additional quality comparator; do not use that arithmetic-mismatched path as the port's fidelity oracle. Gold references and scorer policies stay unchanged.

Initial numerical gates are engineering acceptance limits, not measurements already achieved:

| Comparison stage | Gate | Reason |
| --- | --- | --- |
| Tensor conversion and metadata | Exact logical values after the declared inverse layout transform, exact shapes/vocabulary/blank/lengths | Conversion is a representation change and has no numerical error budget |
| F32 frontend versus floating reference frontend | Elementwise `abs(error) <= 1e-4 + 1e-4 * abs(reference)` | FFT and reduction ordering may differ; frame count, padding, normalization, and mel geometry must still agree |
| F32 subsampling, each encoder block, and logits | NRMSE <= `1e-3` and cosine similarity >= `0.99999` at every checkpoint | Allows accumulated F32 reduction differences while detecting wrong layouts, RoPE, normalization, or layer ordering locally |
| F16 native path subsampling and each encoder block | NRMSE <= `1e-2` and cosine similarity >= `0.9999` at every checkpoint | Metal matrix reduction arithmetic may differ from the diagnostic path; testing every block prevents a final aggregate from hiding an early mismatch |
| F16 native path final logits | NRMSE <= `1e-2`, cosine similarity >= `0.9999`, and exact collapsed CTC token IDs on diagnostic speech fixtures | A small average tensor error alone does not establish decoder parity |

Use `NRMSE = RMS(native - reference) / max(RMS(reference), 1e-6)`. For a near-zero reference tensor, require RMS error <= `1e-6` instead of applying cosine similarity to a zero norm. Reject NaN/Inf. Report maximum absolute error and frame disagreements as diagnostics as well as gate values. Exact CTC blank/repeat fixtures test collapse independently. These tolerances allow arithmetic variation, not changed transcripts. A failure blocks acceptance and requires investigation or a reviewed design/spec update before a limit changes; do not tune tolerances after inspecting WER to make the result pass.

The F32 graph/layout diagnostic may use the already permitted CPU encoder to
isolate graph correctness from Metal matrix arithmetic. Record its actual
backend explicitly. F32 storage alone does not prove full-F32 matrix operands
inside a Metal kernel. Preserve any failing F32/Metal comparison independently;
a CPU diagnostic does not replace the primary F16/Metal gate or relabel a
failed Metal run as passing.

For primary F16 acceptance, require per-recording transcript equality with the matched-window floating reference after only the frozen base normalization, and preserve the frozen research F16-stock25 base-normalized outputs and all aggregate scoring protocols. The existing whole-input matched-F32 check remains reusable evidence for its own context. Preserve raw differences in the report. Quantization has no claim to floating tensor parity: report Q8 per-stage errors and use its separate full-corpus no-regression gates. F16 must pass first. A failing optional Q8 candidate remains experimental and unavailable as an accepted package variant. Its documented evaluation can finish without weakening the gate or blocking independently accepted F16.

### Freeze scoring and record full evidence

Use accepted snapshot `c49eabd7e9a517bb85185f61c7b182af127071d3eaaa8ec49f8fc624fdec4561` with 27 original Float32 WAV recordings, total 969.232 seconds, maximum 81.152 seconds. Six recordings are at most 25 seconds and 21 exceed it. Verify snapshot/audio digests and sample counts on every run. User-accepted references, including the existing two unclear markers, remain fixed; do not reopen reference review or silently remove difficult cases. Preserve the scorer's explicit unclear-marker handling in the versioned protocol.

Run the matched-window F32-activation floating reference and primary native F16 storage on all 27 inputs with identical logical source weights, audio, retained/context spans, and decoding options. Evaluate optional native Q8 under the same window policy. Preserve whole-input outputs as a separately labeled diagnostic. Keep the default MLX F16-activation and earlier MLX INT8 runs separate from the matched arithmetic oracle. Save raw output, normalized output, per-recording and aggregate word/character substitutions, deletions, insertions, denominators, alignments, WER, and CER. Base normalization is the existing NFKC, casefold, yo-to-ye, punctuation, and spoken-number 0..99 protocol, with spaces retained for CER. Pin scorer code and normalization policy digests.

Also save the frozen term-spelling diagnostic and the explicit hesitation-removal diagnostic, including their composition and policy hashes. Existing policy sources are `.local/asr-quality/evaluations/gigaam-20261019/term-spelling-policy.json` and `.local/asr-quality/evaluations/transcribe-cpp-20261019/rescore_hesitations.py`. Do not add candidate-specific semantic substitutions; distinct terms such as ML and email stay distinct. Diagnostics never replace the base metric. Q8 acceptance requires no per-recording regression in normalized word or character edit counts against accepted F16 under the base protocol and no aggregate WER/CER regression under all declared protocols. This is a conservative zero-degradation acceptance rule for this small corpus, not a predicted model score.

Record failures and omissions, stage timings, cold load, warmed inference, repeated-run median and distribution, real-time factor, peak resident/Metal memory where measurable, backend proof, machine/OS identity, and thread/build settings. Use the same repetition policy for paired performance comparisons and separate conversion/load time from inference. Performance is reported, with no unmeasured latency or universal accuracy guarantee. The corpus is private and intentionally difficult; keep audio, transcript artifacts, and model files under ignored local storage. Commit only tooling, manifests without private content, and shareable summaries.

### Make interface behavior and packaging independently testable

Use capability-derived defaults. Expose the checkpoint's languages from metadata. Translation, prompt/glossary controls, beam search, streaming, and finer timestamps are unsupported unless explicitly implemented and tested for this profile. Preserve an upstream-supported feature only after a direct behavior test proves it works for the new checkpoint. Verify explicit unsupported requests return the existing appropriate status. Do not imply that automatic multilingual recognition is a controllable forced-language decoder or that CTC timestamps equal Whisper timestamps.

Test required-Metal initialization and inference from the packaged client with actual backend/scheduler diagnostics. The baseline split is host frontend, Metal encoder graph, host CTC linear projection and greedy search/collapse. The learned CTC projection is model computation, so report and time its actual placement separately rather than inferring whole-model GPU execution from the encoder device. Reject a CPU encoder fallback under required Metal. Cover missing kernels, unavailable device, OOM, model corruption, and invalid parameters. Check abort callbacks at frontend/chunk boundaries and inside graph execution where the backend supports them; the test must prove callback observation through a deterministic execution checkpoint and complete within a fixed watchdog, without a flaky performance assertion. Do not add app-style Swift task cancellation semantics to this native API.

Carry the completed A/B evidence into the maintained fork and reproduce applicable checks when code or build inputs change. A future head-placement comparison must use the same checkpoint, encoder outputs, audio, options, precision, and complete 27-recording snapshot. Compare head tensors within the relevant floating gates, collapsed token IDs and normalized transcripts, all quality protocols, projection time where isolated, transfer/synchronization time, end-to-end latency, and memory. Pair repeated runs using the same warmup/repetition policy and alternate candidate order to expose thermal or ordering bias. Report the paired distribution and observed run-to-run noise, not only a single microbenchmark. Select the Metal projection only if parity/quality gates pass and end-to-end improvement exceeds that measured noise. A head-only speedup without a repeatable end-to-end improvement retains the host baseline. Record the selected placement and evidence in the artifact manifest; head placement is not a new VoicePen setting. A failed or inconclusive experiment does not block a correct F16 host-head port, and no performance SLA is introduced.

Digital silence must decode to no speech. Empty/too-short or non-finite samples follow the native validation statuses. Preserve partial-result ownership on abort and release resources on both success and failure. Repeated load/run/cancel/free tests and a successful request after failure/cancellation guard against stale state. Regression coverage includes all four upstream GigaAM v3 profiles and affected shared frontend/backend/loader paths, plus the existing upstream suite.

### Keep updates and rollback deliberate

A manifest binds fork source, patch list, upstream baseline, ggml, build inputs, library interface/resource version, model revision, precision map, converter/reference/scorer versions, artifact digests, licenses, and acceptance report IDs. Validate license text and redistribution conditions for upstream code, ggml, source weights, and the MLX-derived conversion input separately. Hub tags alone are not sufficient license evidence. Missing provenance or incompatible redistribution terms block artifact acceptance/publication.

Rebuild the same pinned conversion twice and require identical model digests. Build the library twice in clean directories, compare package contents, and account for toolchain UUID/signing metadata if full binary digests differ. Run the clean C/Swift client without Python/MLX on PATH and without the source checkout. Keep a known-good package pin and immutable local artifacts. Update only after the complete applicable gate set passes, with a minimal patch review and upstream contribution candidates recorded. Rolling back selects the previous package/model pair; no application data migration is introduced.

Record a reviewed host-local acceptance attestation separately from distribution
acceptance when the minimum target OS is not available for runtime testing.
It binds the exact package/model/runtime hashes to the verified host and does
not claim compatibility testing on another OS. The immutable candidate manifest
stays unaccepted for distribution until that external gate passes. A host-local
attestation never authorizes publication.

## Risks / Trade-offs

- The windowed encoder bounds per-window attention memory, but the full frontend and stitched sequence still grow with input length. Measure the longest input, report peak memory, and fail explicitly on OOM. Whole-input diagnostics may consume more memory and must not become an implicit fallback.
- Similar encoder structure can hide frontend or layout errors. Exact tensor accounting and per-stage comparisons precede corpus claims.
- Q8 may alter near-tied CTC decisions. Its zero-degradation gate can block Q8 availability while F16 remains a valid candidate; do not advertise completion of both variants prematurely.
- A small fork adds maintenance cost. Keep upstream v3 behavior isolated, patch ownership documented, and update gates reproducible.
- Upstream tool build flags can expose missing shared example headers. Add clean library-only and library-plus-required-tools build jobs, fix only required fork packaging dependencies, and report unrelated upstream target failures explicitly.
- Private corpus availability limits CI portability. Run public/synthetic contract fixtures in ordinary CI and require the private full-corpus job for accepting dependency artifacts. Record skipped private jobs as missing acceptance evidence.

## Migration Plan

Start from the preserved research handoff, promote the converter/profile and stock25 policy into the isolated maintained fork, close the named validation gaps, then produce local candidate packages and reports. Review the evidence and ADR before accepting a dependency pin. Hosting, publication, and VoicePen adoption require separate explicit work. This proposal changes no existing installed app model or user setting. Archive only after implementation gates pass and the new capability is synced into main specs.
